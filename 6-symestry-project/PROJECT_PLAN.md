# План разработки финального проекта

## Что уже есть

- Vite + React + TypeScript.
- Заведены пустые файлы страниц регистрации, входа и главной страницы.
- Redux, маршрутизация, UI-библиотеки и бизнес-логика ещё не подключены.
- Переданный `.fig` удалось прочитать: миниатюра показывает несколько экранов и адаптивных вариантов. Видны авторизация, финансовая панель с таблицами/отчётами, мобильные состояния, светлая палитра с оранжевыми акцентами.
- Миниатюра не позволяет уверенно прочитать подписи и размеры. Перед точной вёрсткой нужно открыть макет в Figma либо получить экспорт отдельных экранов.

## Предлагаемая структура после изучения доски

```text
src/
├── app/                 # App, маршруты, store, типизированные Redux-хуки
├── pages/               # LoginPage, RegisterPage, DashboardPage
├── components/
│   ├── layout/           # Header, навигация, каркас страницы
│   └── ui/               # Общие кнопки, поля, селекты, уведомления
├── features/
│   ├── auth/             # Формы и логика входа/регистрации
│   ├── transactions/     # Форма операции, таблица, slice и селекторы
│   └── reports/          # Сводка, выбор месяца, диаграммы
├── styles/               # Общие токены и базовые стили
└── utils/                # Форматирование дат и сумм
```

Секции расходов, доходов и отчётов на одном дашборде следует собирать из небольших компонентов. Если в макете эти секции доступны как отдельные страницы, их можно оформить как дочерние маршруты без дублирования шапки и состояния операций.

## План по коротким этапам

1. **Сверить детали макета.** Зафиксировать тексты, размеры и поведение экранов входа, регистрации и финансовой панели по отдельным экспортам из Figma.
2. **Поднять каркас интерфейса.** Настроить React Router, страницы входа/регистрации/кошелька, общий Header и адаптивные стили для 320, 768 и 1200 px.
3. **Сделать входной сценарий.** Реализовать формы с Formik и валидацией, локальную авторизацию для учебного проекта, выход и уведомление.
4. **Описать модель операции.** Общая запись `Transaction` с `id`, `type`, `description`, `category`, `amount`, `date`. Добавление/удаление и очистка формы.
5. **Подключить Redux Toolkit.** `authSlice`, `transactionsSlice`, store, типизированные хуки и селекторы; вычисления баланса и помесячных сумм держать в селекторах.
6. **Собрать отчёты.** Переключатель доход/расход, суммы по месяцам текущего года, выбор месяца и Chart.js по категориям расходов.
7. **Довести внешний вид и состояния.** Проверить адаптивность, пустые списки, ошибки формы, загрузку и toast при выходе.
8. **Финальная проверка.** Пройти пользовательский сценарий вручную и устранить ошибки TypeScript/линтера.

## Чтобы не терять время

- Сначала сделать весь основной сценарий на локальных данных; серверную авторизацию не добавлять, если её нет в задании.
- Не подключать сразу несколько UI-систем. Выбрать один подход после просмотра макета; для небольшого проекта достаточно собственных компонентов и одной библиотеки диаграмм.
- Не хранить баланс отдельным состоянием: вычислять его из доходов и расходов, чтобы значения не расходились.
- После каждого этапа запускать имеющиеся `npm run build` и `npm run lint`.
