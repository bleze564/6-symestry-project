# InvestIQ

Застосунок для обліку особистих доходів і витрат. Стек: React, TypeScript, Redux Toolkit, Express і MySQL.

## Необхідне ПЗ

- Node.js 22 або новіший
- MySQL Server 9.x
- MySQL Workbench для налаштування бази

## 1. Відкрийте проєкт

Клонуйте або завантажте репозиторій і відкрийте кореневу папку проєкту у VS Code. У ній розташовані `src/`, `server/` і `package.json` фронтенду.

## 2. Створіть базу даних

1. Запустіть службу MySQL Server.
2. Відкрийте MySQL Workbench і підключіться до локального MySQL під обліковим записом адміністратора.
3. Відкрийте в Workbench файл `server/schema.sql`.
4. У скрипті замініть `replace-with-your-local-password` у команді `CREATE USER` на надійний локальний пароль.
5. Виконайте весь скрипт кнопкою з блискавкою. Він створить базу `investiq`, таблиці `users` і `transactions`, а також користувача `investiq_app` з обмеженими правами.

Якщо користувач `investiq_app` уже існує, `CREATE USER IF NOT EXISTS` не змінить його пароль. Задайте його окремо у Workbench і видайте права на базу:

```sql
ALTER USER 'investiq_app'@'localhost' IDENTIFIED BY 'your-local-password';
GRANT SELECT, INSERT, UPDATE, DELETE ON investiq.* TO 'investiq_app'@'localhost';
```

Використайте той самий пароль на наступному кроці.

## 3. Налаштуйте API

У кореневій папці проєкту скопіюйте шаблон змінних середовища:

```bash
cp server/.env.example server/.env
```

Відкрийте `server/.env` і вкажіть у `DB_PASSWORD` пароль користувача `investiq_app`. Для локального MySQL залиште інші значення без змін:

```env
DB_HOST=localhost
DB_PORT=3306
DB_USER=investiq_app
DB_PASSWORD=your-local-password
DB_NAME=investiq
PORT=3001
```

Якщо пароль містить `#`, пробіли або спеціальні символи, візьміть його в подвійні лапки. Не додавайте `server/.env` до Git: файл містить локальні облікові дані й ігнорується Git.

## 4. Встановіть залежності

Відкрийте термінал у кореневій папці проєкту та встановіть залежності фронтенду:

```bash
npm install
```

У другому терміналі, також відкритому в корені проєкту, встановіть залежності API:

```bash
cd server
npm install
```

## 5. Запустіть застосунок

У терміналі API, який зараз перебуває в папці `server`, запустіть сервер і залиште його працювати:

```bash
npm start
```

У терміналі має з'явитися повідомлення `Server running at http://localhost:3001`.

В окремому терміналі, відкритому в корені проєкту, запустіть фронтенд:

```bash
npm run dev
```

Відкрийте локальну адресу, яку покаже Vite, зазвичай це `http://localhost:5173`. Vite пересилає запити `/api` на сервер за адресою `http://localhost:3001`.

## 6. Перевірте налаштування

Відкрийте `http://localhost:3001/api/health/db`. Якщо підключення до бази працює, сервер поверне:

```json
{"connected":true}
```

На сайті зареєструйте обліковий запис, додайте дохід або витрату й оновіть сторінку — операція має залишитися у списку. Вийдіть з облікового запису та увійдіть знову, щоб перевірити завантаження даних.

## Усунення проблем

- **`Request failed` або `404` під час реєстрації:** перезапустіть API з папки `server` командою `npm start`. Якщо змінювався `vite.config.ts`, перезапустіть і Vite. Обидва термінали мають залишатися відкритими.
- **`Access denied for user`:** перевірте `DB_USER` і `DB_PASSWORD` у `server/.env`. Якщо MySQL-користувач уже існував, виконайте команди `ALTER USER` і `GRANT` вище.
- **База або таблиця не знайдена:** повторно відкрийте та виконайте `server/schema.sql` у Workbench.
- **Електронна пошта вже зареєстрована:** увійдіть у цей обліковий запис або зареєструйте інший.
- **Порт уже зайнятий:** зупиніть старий процес API або Vite через `Ctrl+C` і запустіть його знову.
- **Немає з'єднання з MySQL:** перевірте, чи запущена служба MySQL Server, а також значення `DB_HOST` і `DB_PORT`.

## Примітки

Облікові записи й операції зберігаються в MySQL. Паролі зберігаються у вигляді scrypt-хешів. Локальні API-сесії зберігаються в пам'яті сервера, тому після його перезапуску потрібно увійти знову. Ця конфігурація призначена для локальної демонстрації навчального проєкту, а не для production-хостингу.
